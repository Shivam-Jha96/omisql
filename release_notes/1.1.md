# Release 1.1

*Date: 2026-09-21*

OmniSQL 1.1 introduces the **O(1) Memory Streaming Architecture**, enabling the linter to parse and validate multi-gigabyte warehouse dumps with a constant, minimal memory footprint. It also ships with robust regex pre-processing and native Snowflake dialect support.

## 🚀 Features
- **O(1) Memory Streaming Architecture**: Completely overhauled the core parsing engine to use a byte-by-byte `StreamingSqlReader`. This allows OmniSQL to lint massive data dumps (e.g., 4GB+) without hitting OS memory limits, scaling linearly with disk I/O.
- **On-the-Fly Data Bypassing**: The streaming reader now instantly fast-forwards through massive `COPY ... FROM stdin;` data payloads and drops unsupported DDL statements *before* they reach the AST parser, saving gigabytes of memory.
- **Style Auto-Fixer Heuristics**: Added a file-size safeguard that automatically disables the style auto-fixer (`--fix`) for files larger than 100MB to prevent excessive memory buffering.
- **Snowflake Dialect Support**: Implemented a regex pre-processor and extended the CLI to accept `--dialect snowflake`, enabling native linting for Snowflake-specific SQL syntax and JSON path traversal syntax.

## 📝 Documentation
- **Dialect CLI Usage**: Added documentation to all distribution READMEs detailing how to explicitly set the SQL dialect (e.g., `--dialect snowflake`).
- **Implementation Plan Sync**: Reorganized documentation into the `docs/` folder, added it to `.gitignore` to keep the root clean, and updated `CONTRIBUTING.md` to reflect these changes.

## 🛠️ Maintenance & Chores
- **Regex Pre-Processor Fixes**: Merged PR #15 to correctly intercept and strip out raw data blocks and unparseable PostgreSQL DDLs, preserving exact line numbers for accurate lint reporting.
